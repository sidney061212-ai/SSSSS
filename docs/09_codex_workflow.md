# 《折光回廊》Codex 协作工作流

## 1. 当前阶段原则
本仓库当前只用于微信小游戏策划文档整理与版本收口。Codex 在这个阶段的职责是把玩法、关卡、页面流程和范围边界写清楚，而不是提前生成工程结构。

当前阶段明确不做：
- 不新建代码目录
- 不创建 `package.json`
- 不创建 `src`
- 不安装依赖
- 不擅自生成玩法原型代码

## 2. 文档协作目标
- 统一所有文档中的平台定位为微信小游戏
- 统一交互描述为手机竖屏单指点击
- 统一版本阶段为 Prototype 0.1、Prototype 0.2、MVP 0.3、MVP 1.0
- 统一页面流转为 Loading / Boot、Home、LevelMap、Gameplay、FailResult、ClearResult、Settings

## 3. 推荐交给 Codex 的任务
- 把玩法规则改写成更清晰的单击交互说明
- 细化 8 关草案的失败点和不服感设计
- 统一结果页文案与按钮措辞
- 检查多份文档之间是否出现范围冲突
- 补全资产清单里的代码绘制与 AI imaging 划分

## 4. 暂时不要交给 Codex 的任务
- 在范围未冻结前建立小游戏工程
- 未确认机制前扩展到 20 关以上
- 未验证玩法前设计复杂活动系统
- 在没有评审的情况下加入第二操作方式

## 5. 推荐协作顺序
1. 先说明这次要改哪一类文档。
2. 让 Codex 先核对现有版本定义和页面流程。
3. 再要求 Codex 直接修改文档，而不是只写建议。
4. 最后要求 Codex 输出修改文件列表、主要修正点、待确认问题。

## 6. 推荐提示模板

### 模板 A：检查统一性
“请检查 `docs` 下所有文档是否仍然统一为微信小游戏、竖屏、点击操作，并直接修正文档中的偏差。”

### 模板 B：细化关卡
“请基于 `docs/05_level_design.md`，把第 5 到第 8 关的常见失败位置和挫败感设计写得更具体，不要新增新机制。”

### 模板 C：收口版本范围
“请对照 `docs/02_mvp_scope.md` 与 `docs/07_development_plan.md`，删除超出 Prototype 0.2 和 MVP 0.3 的过度设计。”

## 7. 输出验收标准
- 不再出现旧平台、旧交互和自由游逛式结构残留。
- 所有关卡描述都符合 30 到 90 秒短局逻辑。
- 失败页文案始终围绕“不服”和“差一点”。
- 资产清单清楚区分代码绘制和 AI imaging。

## 8. 进入实现阶段前的门槛
只有满足以下条件，才适合开始后续工程搭建：
1. `01_game_design.md` 已冻结单指点击规则
2. `02_mvp_scope.md` 已冻结四阶段范围
3. `04_screen_flow.md` 已冻结页面结构
4. `05_level_design.md` 的 8 关草案已评审通过

## 9. 提交流程建议
- 单次提交围绕一个明确主题，例如“重写微信小游戏策划方向”。
- 提交前全文搜索旧设定残留，避免文档自相矛盾。
- 提交说明直接写清这次收口的是平台、玩法还是版本范围。
