# 《折光回廊》风险与决策记录

## 1. 已确认决策

| 编号 | 决策 | 原因 | 影响 |
| --- | --- | --- | --- |
| D-001 | 项目定位为微信小游戏 | 决定交互、节奏、界面尺寸和传播方式 | 所有设计都围绕手机竖屏展开 |
| D-002 | 核心操作只有点击 | 降低上手门槛，适合碎片场景 | 不引入拖拽、摇杆、多按钮 |
| D-003 | 单局时长控制在 30 到 90 秒 | 保证短局挑战成立 | 不做长流程内容作为主体验 |
| D-004 | 失败后 1 秒内可重试 | 重试冲动是产品关键留存点 | 结果页与加载必须足够轻 |
| D-005 | 当前先做 8 关草案 | 避免一开始把内容体量拉太大 | 先验证 0.3，再扩 1.0 |
| D-006 | 视觉采用清亮玻璃拟态方向 | 更适合轻休闲用户和短局产品调性 | 不走工业、破败、深色压迫风格 |

## 2. 主要风险

### R-001：点击玩法过于单薄
- 表现：玩家理解很快，但觉得两三关后没有新鲜感。
- 缓解措施：
  - 每关只增加一个新判断点，但节奏上持续制造末段变化。
  - 尽快验证移动棱镜和延迟棱镜是否足够撑开差异。

### R-002：延迟棱镜像卡顿而不像机制
- 表现：玩家误以为游戏掉帧或输入没响应。
- 缓解措施：
  - 给延迟棱镜明显的预热闪烁。
  - 保证延迟时长稳定且短。
  - 首次出现时用一句很短的提示说明“会慢半拍”。

### R-003：失败页太轻，无法激发不服感
- 表现：玩家点到失败页后直接退出，不想再来。
- 缓解措施：
  - 固定使用“差一点就亮了”等文案。
  - 把进度条停在高位。
  - 主按钮视觉权重明显高于其他按钮。

### R-004：视觉太淡导致可点击元素不够突出
- 表现：整体好看，但玩家不知道哪里能点。
- 缓解措施：
  - 棱镜常态保留微弱呼吸光。
  - 可点击态描边和光线轨迹对比度必须足够。
  - 装饰层级永远低于玩法层级。

### R-005：MVP 1.0 传播功能过早膨胀
- 表现：每日挑战、分享、皮肤展示抢走核心玩法开发资源。
- 缓解措施：
  - 只有当 MVP 0.3 的 8 关闭环稳定后，才补 1.0 包装功能。
  - 分享文案和皮肤展示只做基础版，不做复杂系统。

## 4. 范围控制原则
1. 只要一个新想法需要新增输入方式，就默认不进当前版本。
2. 只要一个新想法会拖慢失败后重开，就默认降优先级。
3. 只要一个视觉提案影响光路可读性，就默认不采用。
