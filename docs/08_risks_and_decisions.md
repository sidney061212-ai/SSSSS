# 《折光回廊》风险与决策记录

## 1. 已确认决策

| 编号 | 决策 | 原因 | 影响 |
| --- | --- | --- | --- |
| D-001 | 采用单人线性解谜结构 | 降低内容制作成本，保证节奏稳定 | 不支持自由探索大地图 |
| D-002 | 采用俯视角 2D 表现 | 更利于读光路与快速迭代 | 放弃高沉浸 3D 漫游感 |
| D-003 | MVP 只保留红光与蓝光两种派生光 | 机制足够形成组合，不必早期膨胀 | 关卡上限依赖布局深度而非颜色数量 |

## 2. 主要风险

### R-001：谜题可读性不足
- 表现：玩家知道要开门，但看不懂哪条光路才是关键。
- 触发阶段：前中期任何房间都有可能出现。
- 缓解措施：
  - 限制单房间交互点数量。
  - 给关键门框加颜色灯条。
  - 先改布局，再考虑补提示文本。

### R-002：颜色机制对部分玩家不友好
- 表现：分不清红蓝或不知道不同颜色有什么意义。
- 缓解措施：
  - 提供色盲辅助粒子形状。
  - 门锁和桥面投影除了颜色，还要有不同图标。
  - 首次引入时做单变量教学房间。

### R-003：叙事喧宾夺主
- 表现：日志太长，玩家频繁停下来读文本，破坏解谜节奏。
- 缓解措施：
  - 每段日志不超过 80 字。
  - 日志只放在房间收束点，不放在解谜中段。
  - 文案只回答“为什么继续往前走”。

### R-004：关卡后期复杂度上升太快
- 表现：前 6 个房间顺畅，后 3 个房间突然卡死大多数玩家。
- 缓解措施：
  - 每个新组合先在中难度房间出现一次。
  - 最终房间只做已有机制组合，不再上新规则。
  - 试玩时重点记录 R09 到 R12 的耗时。

### R-005：范围失控
- 表现：团队在实现过程中想加入敌人、潜行、多结局等额外内容。
- 缓解措施：
  - 所有新增想法只记入待定列表。
  - MVP 期间不得新增系统级功能。
  - 任何超范围工作必须先经过文档评审。

## 4. 范围变更原则
1. 能删则删，优先删复杂度而不是加提示。
2. 任何需要新 UI、新教程、新资源链的想法，都默认不是 MVP。
3. 如果一个想法不能直接提升“看懂光路”和“解谜成就感”，优先级下调。
