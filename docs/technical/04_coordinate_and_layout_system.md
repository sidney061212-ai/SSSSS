# 《折光回廊》坐标与布局系统

## 1. 文档目标
本文用于统一竖屏适配、逻辑坐标、真实像素映射和关卡元素布局规则，避免后续出现“关卡数据写的是一套，真机渲染又是另一套”的问题。

## 2. 竖屏适配策略
逻辑设计尺寸建议采用：
- `width = 375`
- `height = 812`

说明：
- 这是逻辑坐标，不是实际设备像素。
- 关卡、镜子、出口、HUD 都先按照这套竖屏尺寸布局。
- 不同手机只做映射和安全区调整，不改动关卡原始逻辑坐标。

## 3. 坐标系统
推荐采用“双坐标系统”：

### 3.1 逻辑坐标
- 所有关卡数据都使用逻辑坐标。
- 所有交互命中也先换算到逻辑坐标中处理。

### 3.2 物理像素坐标
- Canvas 按真实屏幕像素创建。
- 渲染时把逻辑坐标映射到物理像素。

### 3.3 `devicePixelRatio`
- 需要根据 `devicePixelRatio` 放大画布实际像素尺寸。
- 绘制上下文再按比例缩放回逻辑坐标。
- 这样可以保证光线、镜子边缘和文字在高清屏上不模糊。

## 4. 渲染映射原则
- 保持等比缩放，不拉伸关卡区域。
- 优先完整显示中间玩法区域。
- 屏幕更高时增加上下留白，不改变元素相对关系。
- 屏幕更窄时优先保护顶部 HUD 和底部工具栏的可点击性。

## 5. 游戏区域布局
竖屏布局建议：
- 顶部 HUD：约 `80` 逻辑像素
- 中间关卡区：主要玩法区域
- 底部工具栏：约 `120` 逻辑像素

建议分配：
- 顶部放关卡名、镜子数、重置按钮、提示文字。
- 中间保留最大可视面积给关卡区域。
- 底部仅保留少量辅助按钮，避免遮挡解谜画面。

## 6. 安全区处理
- 需要考虑顶部刘海区域和底部 Home Indicator。
- 顶部 HUD 和底部按钮应加安全边距。
- 关卡主区域尽量避开极端边缘，让拖动手势更稳定。

## 7. 关卡元素坐标规范
关卡数据使用逻辑坐标，不直接使用屏幕像素。

示例：
```ts
source: { x: 24, y: 420 }
exit: { x: 350, y: 260 }
mirror: { x: 180, y: 520 }
```

规范：
- `x` 以左上角为 0 向右增长。
- `y` 以左上角为 0 向下增长。
- 所有关卡元素都落在关卡区域的逻辑矩形中。

## 8. 关卡边界与放置边界
建议拆分两个矩形：
- `bounds`：整块关卡逻辑边界
- `placementBounds`：镜子允许拖动的活动边界

这样做的好处：
- 出口和光源可以靠近边缘展示。
- 镜子拖动区域可以更内收，减少误拖出画面的问题。

## 9. 吸附与拖动策略
Prototype 0.1 建议采用：
- 自由拖动
- 45° 角度吸附

第一版明确采用：
- 镜子位置为自由拖动，不做网格吸附。
- 镜子角度采用 `45°` 步进旋转。
- 有效朝向为 `0° / 45° / 90° / 135°`。

这样选择的原因：
- 首关“错位的光”只需要一面镜子完成一次反射，4 个有效朝向已经足够。
- 比自由旋转更稳，更利于触摸操作。
- 比只保留 `45° / 135°` 更有扩展性，后续第 2 关和第 3 关更容易沿用。

## 10. 输入坐标换算
后续实现时，所有触摸点都应做如下处理：
1. 从系统返回的物理像素坐标获取触点。
2. 减去安全区偏移。
3. 按缩放比换算到逻辑坐标。
4. 再做镜子命中检测和按钮命中检测。

## 11. Prototype 0.1 的布局建议
- 顶部显示关卡标题、当前镜子数、重置。
- 中间关卡区占屏幕主体。
- 底部只保留最少按钮，不做复杂道具栏。
- 第 1 关默认镜子初始位置和角度应尽量接近正确解，降低学习门槛。

## 12. 本阶段做什么
- 确定逻辑尺寸、映射方式和安全区规则。
- 确定关卡坐标全部使用逻辑坐标。
- 确定 Prototype 0.1 采用自由拖动 + 45° 步进旋转。

## 13. 本阶段不做什么
- 不实现横屏适配。
- 不实现多分辨率的复杂响应式布局系统。
- 不实现网格编辑器。
- 不实现自由旋转手柄。
