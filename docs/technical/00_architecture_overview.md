# 《折光回廊》技术架构总览

## 1. 文档目标
本文用于定义《折光回廊》Phase 2 的统一技术方向，确保后续进入代码阶段时，所有实现都围绕微信小游戏、手机竖屏、平面光路解谜这三条主线展开。

## 2. 项目技术定位
《折光回廊》第一阶段采用微信小游戏原生能力 + Canvas 2D 绘制实现，不引入重型游戏引擎，不做 3D，不做复杂物理引擎。

这一定位意味着：
- 运行平台是微信小游戏，不额外做 PC 或浏览器玩法适配。
- 玩法表现依赖 2D 几何和代码绘制，不依赖大型位图或复杂特效管线。
- 实现重点是“关卡数据 + 光路模拟 + 触摸交互 + 轻量 UI”，不是搭建大型通用框架。

## 3. 第一阶段目标
Prototype 0.1 只实现第 1 关垂直切片，验证核心玩法是否成立。

必须覆盖的能力：
- 光源发光
- 普通镜子可拖动
- 普通镜子可旋转
- 光线可被镜子反射
- 光能随距离衰减
- 光线进入出口可通关
- 光线未连通时可继续调整
- 支持重置关卡
- 支持简单通关结算

不以本阶段为目标的内容：
- 多关卡流程
- 分光聚能点的正式实现
- 颜色出口
- 登录
- 广告
- 云排行榜
- 商店

## 4. 核心模块
### 4.1 App / Game Bootstrap
- 负责小游戏启动、画布创建、基础配置加载、全局单例初始化。
- 只做启动装配，不承载玩法逻辑。

### 4.2 Scene Manager
- 负责页面级场景切换，例如 Boot、Gameplay、ClearResult。
- Prototype 0.1 可以只保留最小场景集合，但接口命名按长期版本统一。

### 4.3 Game State Machine
- 负责管理“当前处于编辑、提示、通关还是暂停”等状态。
- 用于保证 UI、输入和光路结算都围绕同一状态推进。

### 4.4 Level Loader
- 负责按关卡编号读取 LevelConfig。
- 只加载数据，不直接做渲染和交互。

### 4.5 Level Runtime
- 负责把静态关卡数据转换为当前局内可变状态，例如镜子当前位置、角度、当前用镜数、剩余光能结果。
- 重置关卡时，以 LevelConfig 为源重新生成运行时状态。

### 4.6 Input Controller
- 负责接收触摸输入并转换为镜子选中、拖动、旋转、按钮点击等游戏操作。
- 不直接绘制，不直接计算光路。

### 4.7 Light Simulator
- 负责从光源出发计算直线传播、命中镜子后的反射、光能衰减、是否命中出口。
- Prototype 0.1 采用简化 2D 线段反射模型，不追求真实光学。

### 4.8 Collision / Geometry
- 负责射线与线段、圆、矩形、边界的求交。
- 负责法线、角度、距离、epsilon 等几何计算。

### 4.9 Renderer
- 负责把关卡状态绘制到 Canvas 2D。
- 只读状态，不修改状态。

### 4.10 UI Layer
- 负责顶部 HUD、底部按钮、轻提示、通关卡片等界面层。
- 保持轻量，不引入复杂 UI 框架。

### 4.11 Storage
- 负责本地存储接口预留，例如后续的最高星数、最佳剩余光能、已解锁关卡。
- Prototype 0.1 可只保留接口，不要求正式启用。

### 4.12 Audio，只预留
- 预留音效和背景音乐接口。
- Prototype 0.1 不把音频系统作为核心交付物。

### 4.13 Asset Manager，轻量预留
- 负责后续位图、音频等资源登记。
- Prototype 0.1 以代码绘制为主，只保留轻量资源清单能力。

## 5. 数据驱动原则
- 关卡必须由数据驱动。
- 光源、出口、镜子、障碍、聚光点、评分目标都写在关卡数据里。
- 不要把第 1 关的布局写死在渲染逻辑里。
- 渲染器读取 Level Runtime，Level Runtime 来源于 LevelConfig，形成清晰的数据链路。

## 6. 扩展原则
- Prototype 0.1 不做分光，但架构要允许以后增加分光聚能点。
- Prototype 0.1 不做颜色出口，但关卡数据结构可以预留 `color` 字段。
- Prototype 0.1 不做商店、广告、登录，因此状态机、资源结构和 UI 不为这些系统预留复杂依赖。
- 扩展应基于新增元素类型和模拟规则，而不是推翻现有主循环。

## 7. 本阶段做什么
- 确定微信小游戏原生 Canvas 2D 技术路线。
- 确定未来代码目录结构。
- 确定主循环、状态机、坐标适配、关卡数据结构和光路模拟方案。
- 把 Prototype 0.1 的实现任务拆解为可逐步提交的小任务。

## 8. 本阶段不做什么
- 不写游戏代码。
- 不创建小游戏工程。
- 不创建 `src`。
- 不创建 `package.json`。
- 不安装依赖。
- 不生成素材。
- 不实现任何玩法功能。
- 不改写已确认 GDD。

## 9. 明确不做事项
- 3D
- 物理引擎
- ECS 复杂架构
- 网络同步
- 云存档
- 广告系统
- 商店
- 登录
- 分光实现
- 颜色出口实现
- 大量关卡
