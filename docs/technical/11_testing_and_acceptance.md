# 《折光回廊》测试与验收标准

## 1. 文档目标
本文用于定义 Prototype 0.1 的测试重点和验收口径，保证后续写代码时，验证标准围绕“第 1 关垂直切片是否成立”展开。

## 2. 测试策略
Prototype 0.1 以手动验证为主，重点覆盖：
- 微信开发者工具预览
- 真机预览
- 关卡内重复拖动和旋转
- 光路边界情况

自动化测试不是本阶段前置要求，但关键规则要有清晰的人工验收项。

## 3. 功能验收
- 光源正确发光
- 镜子可拖动
- 镜子可旋转
- 光线可反射
- 光能会衰减
- 光线命中出口能通关
- 光线未命中出口不会误判
- 重置有效

建议检查方式：
- 启动后立即能看到第 1 关初始布局。
- 拖动镜子前后，光线路径明显变化。
- 旋转镜子后，反射方向稳定变化。
- 故意把镜子放错，系统只提示未连通，不误判为通关。

## 4. 交互验收
- 点击目标准确
- 拖动不漂移
- 旋转反馈明确
- 触摸结束后状态正确
- UI 按钮不和镜子操作冲突

建议检查方式：
- 连续点击镜子 5 次以上，角度步进稳定。
- 从镜子中心和边缘拖动，镜子都应跟手。
- 点击重置时，不应误拖镜子。
- `touchcancel` 后不应残留“正在拖动”的错误状态。

## 5. 视觉验收
- 画面清爽
- 不暗黑
- 不复杂棋盘格
- 光线清晰
- 镜子有玻璃感
- UI 不拥挤

建议检查方式：
- 顶部 HUD 不压缩中间关卡区。
- 光线和背景对比足够，不会看不清。
- 镜子选中时有轻微高亮，但不会喧宾夺主。
- 通关卡片风格和主界面一致。

## 6. 性能验收
- 真机预览不卡顿
- 拖动时不明显掉帧
- 光路计算不会无限循环
- `maxBounces` 生效

建议检查方式：
- 持续拖动镜子 10 秒以上，观察光路是否稳定刷新。
- 故意把镜子放在容易多次反射的角度，确认不会卡住。
- 进入后台再回来后，画面能恢复。

## 7. 边界情况
- 镜子拖到边界
- 光线刚好擦过出口
- 光线反复反射
- 光线能量刚好耗尽
- 镜子重叠，Prototype 0.1 可先简单处理
- 多次重置

边界说明：
- 镜子拖到边界时，位置应被限制在合法区。
- 光线擦边命中出口时，应以出口半径和求交规则统一判定。
- 光线能量刚好为 0 时，不应再被判为有效通关。
- 镜子重叠在 Prototype 0.1 可以先不作为复杂问题处理，但不能导致程序异常。

## 8. 建议测试清单
### 8.1 每次开发后都要重复验证
- 进入第 1 关是否正常
- 拖动镜子是否正常
- 点击旋转是否正常
- 光路是否刷新
- 重置是否恢复初始状态

### 8.2 在 Task 6 之后重点验证
- 反射角是否稳定
- 光线是否因距离变暗或中断
- 命中出口是否立即触发通关
- 未命中是否只给轻提示

## 9. 验收结论标准
只有同时满足以下条件，Prototype 0.1 才算通过：
- 玩家能在几秒内看懂目标
- 玩家能通过拖动和点击旋转完成一次反射
- 光线结果稳定、可预期、可复盘
- 通关和重置流程都可用

## 10. 本阶段做什么
- 明确功能、交互、视觉、性能和边界测试标准。
- 明确 Prototype 0.1 以人工验收为主。

## 11. 本阶段不做什么
- 不编写自动化测试代码。
- 不建立性能分析平台。
- 不做多机型全量兼容清单。
