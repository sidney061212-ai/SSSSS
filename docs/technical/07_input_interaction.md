# 《折光回廊》输入交互方案

## 1. 文档目标
本文用于明确微信小游戏环境下的触摸输入、镜子拖动、镜子旋转和交互优先级，确保 Prototype 0.1 的操作简单、稳定、可复现。

## 2. 触摸事件
使用微信小游戏触摸事件：
- `touchstart`
- `touchmove`
- `touchend`
- `touchcancel`

原则：
- Prototype 0.1 只按单指触摸设计。
- 不依赖复杂多指手势。
- 所有触点先换算到逻辑坐标，再做命中判定。

## 3. 输入状态
建议维护以下运行时输入状态：
- `idle`
- `pressed`
- `dragging`
- `selected`

说明：
- `pressed` 用于判断这次触摸是拖动还是点击。
- `dragging` 用于持续更新镜子位置。
- `selected` 表示当前镜子被选中，可以接受点击旋转。

## 4. 拖动镜子
逻辑如下：
1. `touchstart` 命中镜子
2. 记录该镜子为当前目标
3. 进入 `pressed`
4. `touchmove` 超过拖动阈值后进入 `dragging`
5. `touchmove` 持续更新镜子位置
6. `touchend` 结束拖动
7. 标记 `lightDirty = true`

补充要求：
- 拖动过程中镜子轻微放大。
- 位置更新应被限制在 `placementBounds` 内。
- 默认目标是拖动过程中实时更新光路。

## 5. 旋转镜子
Prototype 0.1 为降低复杂度，明确采用：
- 点击选中镜子后按固定角度步进旋转。

推荐具体规则：
- 若 `touchstart` 命中镜子，且 `touchend` 前没有超过拖动阈值，则视为点击。
- 点击已选中镜子时，按 `45°` 步进旋转一次。
- 每次旋转后立即标记 `lightDirty = true`。

这样做的好处：
- 能清楚区分拖动和旋转。
- 不需要额外旋转手柄。
- 便于首关快速上手。

## 6. 后续旋转手柄预留
后续若进入更复杂关卡，可扩展为：
- 点击选中镜子
- 镜子出现旋转控制点
- 拖动旋转控制点改变角度

但在 Prototype 0.1 中，不实现旋转手柄。

## 7. 选择优先级
如果点击命中多个元素，优先级如下：
- UI 按钮优先
- 选中镜子优先
- 普通镜子其次
- 背景最后

说明：
- 先保证按钮可靠点击。
- 再保证选中的镜子不会因为附近元素干扰而丢失控制。

## 8. 拖动边界
镜子不能拖出关卡区。

Prototype 0.1 先做的限制：
- 限制在 `placementBounds` 内。

Prototype 0.1 暂不强制的限制：
- 不与出口重叠
- 不与光源重叠
- 不与障碍重叠

这些约束可以在后续障碍和多元素关卡中逐步加入。

## 9. 手感要求
- 拖动时镜子轻微放大。
- 可放置区域高亮。
- 旋转时角度吸附明确。
- 光路实时更新或松手后更新。

Prototype 0.1 建议：
- 拖动过程中实时更新光路。
- 如果真机性能不足，再退化为松手更新，但默认目标仍是实时反馈。

## 10. 推荐交互流程
### 10.1 初次摆放
- 玩家拖动镜子到光路中间。
- 松手后立刻看到新的反射结果。

### 10.2 调角度
- 玩家点击镜子。
- 镜子按 `45°` 递增旋转。
- 光路立刻刷新。

### 10.3 继续微调
- 玩家继续拖动和点击，直到光进入出口。

## 11. 按钮交互建议
Prototype 0.1 建议只保留以下必要按钮：
- 重置
- 重新挑战，通关后显示

不建议在首版加入：
- 撤销
- 重做
- 提示系统
- 复杂道具栏

## 12. 本阶段做什么
- 确定四类触摸事件的使用方式。
- 确定拖动镜子和点击步进旋转的交互规则。
- 确定命中优先级和拖动边界。

## 13. 本阶段不做什么
- 不实现双指缩放。
- 不实现自由旋转手柄。
- 不实现撤销重做。
- 不实现复杂手势系统。
