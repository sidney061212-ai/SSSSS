# 《折光回廊》渲染与 UI 方案

## 1. 文档目标
本文用于明确 Canvas 绘制层次、Prototype 0.1 的最小页面结构，以及如何把既有 GDD 中“清爽、明亮、玻璃拟态、蓝紫渐变、柔和发光、大量留白”的风格转成可执行的技术规则。

## 2. 渲染分层
建议的渲染顺序如下：
- 背景层
- 关卡底板层
- 障碍层
- 聚光点 / 出口层
- 镜子层
- 光线层
- 粒子 / 命中特效层
- HUD 层
- 弹窗层

补充说明：
- 第 1 关虽然没有障碍和聚光点，但层级顺序仍按长期版本统一。
- 光线层放在镜子层之上，便于让玩家更清晰地看到当前有效路径。

## 3. Canvas 绘制元素
Canvas 2D 需要绘制的元素包括：
- 光源
- 出口
- 镜子
- 光线
- 光线辉光
- 障碍
- 聚光点
- 星级
- 按钮
- 结算卡片

Prototype 0.1 实际会落地的元素：
- 光源
- 出口
- 镜子
- 光线
- 光线辉光
- 顶部 HUD
- 重置按钮
- 简单结算卡片

## 4. UI 页面拆分
长期版本页面：
- `Home`
- `LevelSelect`
- `Gameplay`
- `ClearResult`
- `Settings`

Prototype 0.1 的页面策略：
- 可以不做完整 `Home` 和 `LevelSelect`。
- 可以直接进入第 1 关 `Gameplay`。
- 通关时显示 `ClearResult` 覆盖层。
- 未连通时只显示 `IncompleteHint` 轻提示，不做完整失败页。

## 5. Gameplay 页面建议
### 5.1 顶部
- 第 1 关：错位的光
- 用镜目标：1
- 当前用镜数量
- 重置按钮

### 5.2 中间
- 光源
- 出口
- 镜子
- 光线路径

### 5.3 底部
- Prototype 0.1 保持极简。
- 可不放复杂工具栏，只预留少量空白作为未来扩展区。

## 6. ClearResult 页面建议
通关时显示半透明圆角卡片，包含：
- 光已抵达
- 用镜数量
- 剩余光能
- 重新挑战

可选预留但不要求首版一定展示：
- 星级占位
- 下一关按钮占位

## 7. IncompleteHint 轻提示
建议用轻量方式显示：
- 光路未连通
- 光能不足
- 未抵达出口
- 继续调整

展示位置建议：
- 靠近光线终点
- 或靠近出口区域

不要做成：
- 遮住整个关卡的大弹窗
- 强制关闭后才能继续的阻断式提示

## 8. 视觉风格落地规则
把 GDD 中的视觉方向转成实现规则：

### 8.1 背景
- 使用浅色渐变。
- 推荐从偏白蓝过渡到淡蓝紫。
- 不使用大面积纯黑或深灰。

### 8.2 光线
- 使用蓝白或蓝紫发光。
- 中心线清晰，外层加轻微辉光。
- 能量降低时可通过亮度或透明度略微下降体现。

### 8.3 镜子
- 使用半透明玻璃片表现。
- 边缘有细高光。
- 选中时可加轻微外描边或发光。

### 8.4 UI 面板
- 使用半透明圆角卡片。
- 阴影轻、描边细。
- 不使用厚重实体按钮。

### 8.5 整体取向
- 避免大面积深色。
- 避免复杂棋盘格。
- 避免高饱和按钮。
- 保持大量留白。

## 9. 文本规范
Prototype 0.1 需要的文本：
- 第 1 关：错位的光
- 用镜目标：1
- 光已抵达
- 光路未连通
- 光能不足
- 重新挑战
- 重置

文案原则：
- 统一短句。
- 不使用重惩罚词。
- 不写“失败”。

## 10. 为什么先用代码绘制 UI
- 当前画面元素少，代码绘制更快迭代。
- 不会因为临时切图阻塞玩法验证。
- 能和光路状态更直接联动。

## 11. 本阶段做什么
- 确定渲染层次顺序。
- 确定 Prototype 0.1 的最小 UI 页面和提示形式。
- 确定视觉风格的技术落地规则。

## 12. 本阶段不做什么
- 不实现完整首页包装。
- 不制作复杂关卡选择页。
- 不制作大量位图 UI。
- 不实现复杂粒子系统。
