# 《折光回廊》光线模拟方案

## 1. 文档目标
本文用于明确后续代码阶段的光路计算模型，确保它满足“好玩、清晰、可控”的目标，而不是走向真实复杂光学模拟。

## 2. 简化物理原则
- 不用真实复杂光学。
- 使用 2D 直线传播 + 镜面反射。
- 目标是好玩、清晰、可控，不是物理真实。

这意味着：
- 不做折射。
- 不做曲面镜。
- 不做材质差异。
- 不做连续波动或粒子光学。

## 3. 光线表示
建议以“射线 + 线段链”的形式表示结果。

```ts
interface Ray {
  origin: Point;
  direction: Vector2;
  color: "white" | "blue" | "violet";
  energy: number;
  segments: Segment[];
}

interface Segment {
  from: Point;
  to: Point;
  energyStart: number;
  energyEnd: number;
  hitType: "mirror" | "obstacle" | "absorber" | "condenser" | "exit" | "boundary" | "none";
  hitId: string | null;
}
```

说明：
- `Ray` 表示当前这束光的整体结果。
- `segments` 记录它经历的每一段传播路径。
- UI 可以直接根据 `segments` 绘制光线和末端提示。

## 4. 光线传播流程
单束光的计算流程建议如下：
1. 从光源生成第一条射线。
2. 沿当前方向寻找最近命中对象。
3. 计算从起点到命中点的距离。
4. 按距离扣减光能。
5. 根据命中对象决定是结束、反射、补能还是继续。
6. 重复直到命中出口、能量耗尽、越界或超过最大反射次数。

## 5. 反射计算
### 5.1 镜子表示
- 镜子可简化为线段。
- 线段由中心点、长度和角度推导出两个端点。

### 5.2 求交
- 光线与镜子线段求交。
- 只接受沿前向方向的有效交点。
- 多个命中候选时，取距离最近者。

### 5.3 反射方向
命中镜子后，按镜面法线计算反射方向。

概念公式：
```text
reflected = direction - 2 * dot(direction, normal) * normal
```

说明：
- `direction` 是入射方向单位向量。
- `normal` 是镜面法线单位向量。
- 最终仍使用单位向量作为下一段光线方向。

## 6. 碰撞顺序
每次光线传播时，都要寻找最近命中对象，候选顺序如下：
- 镜子
- 障碍
- 吸光块
- 聚光点
- 出口
- 边界

处理规则：
- 所有对象一起参与求交。
- 选出距离最近的命中点，作为当前 `segment` 的终点。
- 命中出口则结束并判定成功。
- 命中镜子则反射。
- 命中障碍或吸光块则结束并记录未连通原因。
- 命中边界则直接结束。

## 7. 光能衰减
每传播一段距离都消耗光能。

建议公式：
```text
energyCost = distance * decayRate
energyEnd = energyStart - energyCost
```

规则：
- 光能小于等于 `0` 时，光线熄灭。
- 若在到达下一个命中点前光能已耗尽，则终点应截在当前段中途。
- Prototype 0.1 推荐采用线性衰减，优先保证可读性和调试效率。

## 8. 聚光点预留
- 命中聚光点后恢复光能。
- 聚光点可以理解为“先结束当前段，再创建补能后的下一段”。
- Prototype 0.1 不实现聚光点，但 Light Simulator 设计要预留这一结果分支。

## 9. 最大反射次数
为了避免死循环，需要设置 `maxBounces`。

Prototype 0.1 建议：
- `maxBounces = 8`

说明：
- 第 1 关只需要一次反射。
- `8` 足够覆盖后续连续反射关卡，又不会让错误布局无限计算。

## 10. 防止自碰撞
光线刚从镜子反射出去时，要给一个很小的 `epsilon` 偏移，避免立刻再次命中同一镜子。

推荐做法：
- 新射线起点沿反射方向轻推一个很小距离。
- 同时忽略距离小于 `epsilon` 的重复命中。

## 11. 通关判断
通关条件：
- 光线命中出口
- 光线颜色被出口接受
- 命中时能量大于 `0`

在 Prototype 0.1 中可以简化为：
- 单束白光命中单个出口
- 命中时剩余光能大于 `0`

## 12. 未连通原因分类
为了给 `IncompleteHint` 提供轻提示，模拟器应返回未连通原因：
- `noHitExit`：未抵达出口
- `energyDepleted`：光能不足
- `blockedByObstacle`：被障碍阻挡
- `absorbed`：被吸光块吸收
- `outOfBounds`：越界
- `maxBouncesReached`：超过最大反射次数

Prototype 0.1 常用到的只有：
- `noHitExit`
- `energyDepleted`
- `outOfBounds`

## 13. Prototype 0.1 简化范围
第一版只需要：
- 单光源
- 单出口
- 普通镜子
- 光能衰减
- 反射
- 命中出口
- 越界 / 能量耗尽 / 未命中提示

不实现：
- 多光源
- 分光
- 颜色出口
- 聚光点
- 吸光块

## 14. 为什么不做真实光学
- 当前目标是验证玩法，不是做光学演示程序。
- 真实光学会把调参、调试和关卡设计都变复杂。
- 玩家需要的是清晰、稳定、可复盘的光路结果。

## 15. 本阶段做什么
- 定义光线和路径段的数据模型。
- 定义求交、反射、衰减、命中出口的统一规则。
- 约定 `maxBounces`、`epsilon` 和未连通原因。

## 16. 本阶段不做什么
- 不实现真实折射。
- 不实现聚光点或分光聚能点逻辑。
- 不实现多束光并发模拟。
- 不写模拟器代码文件。
